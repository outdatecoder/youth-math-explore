# 数学探索台 · 少儿数学互动学习门户

> 一个给孩子的数学学习入口。用会动的图、能拖的滑块和小实验，把课本上「看不见」的道理变成看得见、玩得懂的东西。

图论 · 概率 · 统计学 · 函数先导 · 微积分（上篇），五个主题，一个入口。

---

## 一、项目目的

**给孩子一个"想点开"的数学入口，而不是一堆散落的学习网页。**

这五份交互学习页是在一段时间里陆续做出来的，每一份本身都完整、能用，但它们之间没有任何联系：分散在**两个不同的目录、两个独立的 git 仓库**里，彼此互不感知。

结果就是：内容做得再好，孩子**找不到门**；家长也没法回答"我该让他先看哪个"。

所以这个门户做的事只有一件，但很关键：**把已有的五份内容串成一条有起点、有顺序、有回头路的学习路径。**

具体到三条设计目标：

| 目标 | 含义 |
|---|---|
| **找得到** | 一个统一入口，六张卡片一目了然，知道自己有多少可看 |
| **有顺序** | 按数学分支分三组，并显式标注前置关系（概率 → 统计学、函数先导 → 微积分） |
| **回得来** | 每页都有回退通路，孩子不需要理解"浏览器后退键"这个概念 |

## 二、解决什么问题

| # | 问题 | 具体表现 | 本项目的处理 |
|---|---|---|---|
| 1 | **内容散落，没有入口** | 五个页面在两个目录、两个 git 仓库里，孩子只能靠家长手动打开本地文件 | 收拢到同一目录 + `index.html` 门户页，一个链接进入全部 |
| 2 | **不知道先看哪个** | 五份内容平级，没有难度与依赖提示 | 按分支分三组 + 卡片上标「建议先看 XXX」 |
| 3 | **进得去，出不来** | 各页原本没有任何回跳链接，只能按浏览器后退 | 每页注入两枚浮动按钮（左上「返回门户」、右下「返回顶部」） |
| 4 | **断网/弱网就白屏** | 图论页依赖 `unpkg.com` 的 Cytoscape，国内不稳定，断网直接白屏 | Cytoscape 本地化到 `vendor/`，全站**零外部请求** |
| 5 | **分享不了** | 中文文件名在公网上会被编码成 `/%E5%9B%BE%E8%AE%BA...`，微信里发出去又长又乱且有兼容差异 | 文件名统一改英文 slug，页面内中文标题不变 |
| 6 | **改一份内容要手动同步五处** | 源仓库持续开发，门户副本会逐渐过期（内容分叉） | 幂等同步脚本，双击一次完成「复制 + 重打补丁 + 自校验」 |
| 7 | **改动容易悄悄失效** | 纯 CSS/JS 的界面问题，肉眼走查看不出来（卡没骑上去、按钮变透明、按钮压住正文） | 两套自动化验证脚本，改完跑一次即可复验 |

## 三、为什么值得用

### 1. 内容不是"知识点罗列"，而是"让看不见的东西看得见"

每份学习页都用交互演示代替文字说明。例如：

- **图论**：可以真的删掉一条边，看它怎样从"不是割点"变成"真割点"；
- **统计学**：亲手拖动数据点，看同一组数字如何得出相反结论（安斯库姆四组）；
- **微积分**：拖滑块让间隔趋近于零，看"一瞬间的变化"是怎么被抓住的。

这是这批内容最核心的价值 —— **它不靠"讲"，靠"玩"**，符合这个年龄段孩子的认知方式。

### 2. 工程上极度省心：零依赖、可离线、单文件

| 特性 | 实际含义 |
|---|---|
| **零外部请求** | 全站无 CDN、无 `fetch`、无网络请求。飞机上、车里、断网的老平板上都能用 |
| **双击即开** | 不需要装任何东西，不需要起服务器（已实测 `file://` 协议下完整可用） |
| **单文件页面** | 每个主题就是一个 HTML 文件，拷走即用，坏不了 |
| **总体积约 1.4 MB** | 六页 + Cytoscape，比一张照片还小，微信传输无压力 |
| **无状态、无存储** | 不用 `localStorage`，不写任何数据，不会互相污染，也不涉及隐私 |

### 3. 儿童向细节是认真做过的，不是"能显示就行"

- **门户**整张卡片可点，不用瞄准小按钮；卡片最小高度 190 px；
- 注入的导航按钮触控高度：桌面 48 px、窄屏（≤520 px）44 px、边距同步内收 16 → 12 px；
- 布局三档手工调过：桌面 3 列 / 平板 2 列（≤920 px）/ 手机 1 列（≤600 px）；
- **门户页**响应 `prefers-reduced-motion`，对动效敏感的孩子不会被打扰；
- 占位卡（微积分下篇）明确灰显不可点，不会让孩子点了没反应还以为坏了。

### 4. 能长期活下去：数据驱动 + 自动化验证

**新增一篇内容，只改一个数组，不碰任何逻辑代码：**

```js
// index.html 里的 CATALOG
{ file: 'graph2.html', title: '图论 · 下篇', chapter: '……', ready: true }
```

**改完能自证没坏：** 两套脚本分别是 `_shot.py`（结构 + 行为 + 视觉走查，64 项断言）和 `_verify_overlay.py`（全子节遮挡验证）。这类界面问题——"按钮压住了文字""卡没骑到色块上"——**截图和肉眼都极容易放过**，脚本能稳定抓住。

## 五、如何使用

### 5.1 最简单的用法：双击打开

直接双击 `index.html` 即可，**不需要任何环境**。

推荐浏览器：Edge / Chrome（Windows）、Safari（iPad / iPhone）。手机平板建议「添加到主屏幕」，之后就像 App 一样一点即开。

> 已实测：`file://` 协议下五个主题页全部完整可用，包括图论页依赖的本地 Cytoscape（`window.cytoscape` 正常加载，版本 3.28.0）。

### 5.2 本地起服务预览（可选，更接近线上环境）

```bash
python -m http.server 8765 --directory "D:/WorkBuddy/7-数学学习门户"
```

然后访问 <http://127.0.0.1:8765/>。

### 5.3 给孩子用：怎么用

1. **进入** —— 打开门户页，六张卡片按三组分好，直接点卡片（整张卡都可点，不用瞄准小按钮）；
2. **阅读** —— 每页内部有自己的知识地图与子节导航，跟着走即可；
3. **回退** —— 左上角常驻「← 返回门户」回到首页；页面长了用右下角「返回顶部 ↑」（向下滚动一段后才会出现）；
4. **顺序建议** —— 推荐先「函数先导」再「微积分 · 上篇」；「概率」放在「统计学」之前。

### 5.4 发布到网上（GitHub Pages）

发布后微信内可直接打开、可分享。步骤：

1. GitHub 网页新建 **public** 仓库（如 `math-explore`），**不要**勾选 Add README / .gitignore；
2. 本地配置并推送：

   ```bash
   git config user.email "<你的 GitHub 邮箱>"
   git remote add origin https://github.com/<用户名>/math-explore.git
   git push -u origin main
   ```

3. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存；
4. 约 1 分钟后访问 `https://<用户名>.github.io/math-explore/`。

仓库内已预置 `.nojekyll`（关闭 GitHub Pages 的 Jekyll 处理）、英文文件名 slug（避免中文 URL 编码）、`.gitattributes`（锁定行尾），这三项就是为发布准备的。

### 5.5 新增一个主题（扩展）

**只需两步，不碰任何渲染逻辑：**

1. 把新页面按命名规则放进本目录；
2. 在 `index.html` 的 `CATALOG` 数组里加一项。

命名规则（重要）：

| 情况 | 规则 | 例子 |
|---|---|---|
| 该学科只有一篇 | `<学科>.html` | `graph.html`、`probability.html` |
| 该学科有多个分篇 | `<学科><篇号>.html`，从 1 起 | `calculus1.html`、`calculus2.html` |

若某学科将来从一篇变多篇（如图论出下篇），为保住已分享出去的旧链接，保留原文件作为跳转页：

```html
<!DOCTYPE html><html><head><meta charset="utf-8">
<meta http-equiv="refresh" content="0; url=./graph1.html"></head>
<body><a href="./graph1.html">正在跳转…</a></body></html>
```

### 5.6 源内容更新后，如何同步过来

**重要前提：本目录里的五个 HTML 是「只读快照」，不要在这里改内容。** 所有内容修改都在源仓库进行，改完同步过来。

```powershell
# 双击即可（内部已处理执行策略限制）
_sync.cmd
```

脚本做四件事，全部自动：**① 从两个源仓库复制并改名 → ② 重打 Cytoscape 本地化补丁 → ③ 重打导航按钮补丁 → ④ 自校验**。跑完看到 `ALL PASS` 即成功，且**可重复运行**（幂等）。

> **为什么补丁要"重打"？** 每次同步都从**源文件**重新读取，而源文件是干净的（没有 CDN 替换、没有返回按钮）。上次的补丁会随覆盖一起消失，所以必须在复制后重新打一遍 —— 这正是脚本存在的意义。

**同步时机建议按里程碑**，不必逐次：源仓库完成"第 N 章收官 / 定稿"这类提交时同步一次即可。

## 七、两条铁律

1. **绝不在本目录手工编辑那五个 HTML。** 下次同步会被源文件覆盖，你的修改会**静默丢失**。

## 八、已知边界

| 事项 | 说明 |
|---|---|
| 源副本会分叉 | 本目录是快照，源仓库更新后必须跑一次 `_sync.cmd`，不会自动同步 |
| 极窄屏导言卡行数 | 门户顶部导言卡在 375 px 真机屏上会到 4 行（屏宽物理限制）；桌面/平板 2 行、500 px 窄屏 3 行 |
| 门户页是手工维护的 | 新增主题只改 `CATALOG` 数组；但若新增**分组**，需同步调整 `.grid` 列数相关样式 |
| 移动端按钮落位 | 统计学页在 ≤900 px 下「返回门户」会落在导语段之后（约 165 px 处）。这是为保住 44 px 触控高度的取舍 |
